## 一、工具中心地图（四分区）

| 分区 | 管什么 |
|---|---|
| **原生 MCP** | 各智能体的 MCP server 统一仓库（添加 / 启停 / 按智能体分发 / 写回各家 CLI 配置） |
| **桥接 MCP** | 把 HTTP 接口、本地命令封装成智能体可调用的工具 |
| **本机 MCP** | 本地进程工具集（终端 / 文件 / 应用 / 截屏）的执行与审批策略 |
| **发现** | MCP 市场三来源浏览与一键安装 |

应用内置 4 个 MCP 服务（记忆桥接、HTTP 工具桥、会话记忆、接口测试），不可删除；侧栏分组还叠加了一张「热榜工具」内置聚合卡。

## 二、原生 MCP：统一仓库

### 添加服务（两条路）

- **一键同步**：反向扫描 Claude Code / Codex / Gemini / OpenCode / Hermes / CodeBuddy / DSH 七家 CLI 已有配置，全部导入统一仓库（best-effort：个别应用失败不影响其他，聚合提示「已导入 N 个，部分应用导入失败」；已存在的只点亮开关、不覆盖你的修改）。
- **手动添加**：标题 + 显示名 + 启用到哪些智能体 + JSON / TOML 配置编辑器；**配置向导**按类型分步（本地命令：命令 / 参数 / 环境变量；远程服务：URL / 请求头）；**预设一键填**（fetch / time / memory / sequential-thinking / context7 / chrome-devtools 等）；**智能粘贴**认三种形态（纯配置对象 / `"名字": {...}` 键值对 / 单键包装）。

### 每智能体分发（圆点开关）

每张 MCP 卡片底部是 10 家智能体的圆点开关：**开 = 把该服务写入该智能体的配置文件**，关 = 从其配置移除。未安装的 CLI 自动跳过（不会凭空创建配置目录）。写入位置各家不同（`~/.claude.json`、`~/.codex/config.toml`、`~/.gemini/settings.json` 等），句芒智元只写自己的受管条目、不碰你手工配置的其他内容。

内置四服务走专属通道：记忆桥接 = 记忆共享注册（见[记忆沉淀](./memory.md)）；会话记忆 = MCP 与钩子原子同步；接口测试 = 智能化测试的测试工具库。

### 连接测试与 OAuth

卡片刷新按钮做**连接测试**（60 秒超时兜底——npx / uvx 型服务首跑要下载依赖，慢是正常的）；远程服务带 OAuth 的显示「登录」按钮（跳系统浏览器授权）。

## 三、桥接 MCP：HTTP 接口与命令

把非 MCP 的东西包成智能体工具，现支持两类：

### HTTP 工具

| 字段 | 说明 |
|---|---|
| 工具名称 / 描述 | 描述是给智能体的工具说明，写清楚用途与场景 |
| HTTP 方法 | GET / POST / PUT / PATCH / DELETE |
| 请求地址 | **URL 模板**：`{参数}` 占位符（如 `{userId}`），参数由智能体运行时提供 |
| 请求头 | KV 行编辑器，值里可用 `{param}` 占位；每行有「参数说明」列 |
| 请求体 | 无 / form-data（KV）/ 原始文本（JSON / XML 等，整块模板） |
| 安全资源策略 | 该工具的资源等级 |

校验：请求头与请求体参数**同名冲突**会拒绝保存；每行参数说明必填（这是给智能体的参数文档）。「测试」按钮直接发一次真实请求验证。

### 命令工具

可执行程序（默认 `node`）+ 参数模板（`{args}` 占位）+ 工作目录 + 超时（默认 60 秒）+ Input Schema（JSON Schema，描述参数）。执行直接拉起进程、按引号规则切分参数、超时杀进程组、输出截断。

### 注册与调用

每个工具注册成独立 MCP 服务（`gromang-http-bridge:<工具ID>`，SSE 形态），卡片圆点即注册 / 注销到各智能体。调用链路：智能体请求 → 本地桥接服务按模板渲染（占位符替换、请求头体填充）→ 执行 → 结果回传（60 秒超时；默认校验 TLS 证书，自签名端点可用环境变量放行）。工具被停用时智能体调用会明确报「工具已停用」。

## 四、本机 MCP：本机工作台

本地进程工具集（终端 / 文件 / 应用 / 截屏），安全全靠两张策略卡：

- **执行模式**：预览模式（默认——只返回操作摘要不实际执行，只读除外）与真实执行；
- **审批策略**：仅写操作审批（默认）/ 从不审批 / 全部审批；待审批操作弹全局审批浮层，逐条放行或拒绝；
- **审计日志**：每次执行的六种结果留痕（已执行 / 预览 / 已拒绝 / 超时 / 被拦截 / 错误），可随时翻查。

## 五、发现：市场安装

三个来源：内置精选目录、官方 MCP Registry、魔搭 ModelScope。「**一键安装**」直接入库并默认分发到主流智能体；无标准安装方式的条目给「查找配置」——预填元数据打开手动表单，你粘配置即可。

## 六、深链导入

`gromang://v1/import?resource=mcp&apps=claude,codex&config=<base64>`——收到深链即弹确认对话框（列出目标应用与服务器清单，警告「导入后将立即写入所有指定应用的配置文件」），确认后批量写入。`apps` 仅支持 claude / codex / gemini / opencode / hermes 五个值。

## 七、与接口测试的联动

内置的接口测试 MCP 服务把测试能力暴露成智能体工具（跑套件 / 断言 / 报告）；反过来，智能化测试的**工具库**（HTTP 工具 / MCP / 本机三个 Tab）允许测试步骤直接引用这些工具——工具试跑与测试断言分离，工具是给智能体复用的模板，测试是对外可验证的断言。

## 八、常见问题 FAQ

**一键同步没导入我的服务？**
仅支持七家 CLI；个别应用配置文件损坏不影响其他家（聚合提示哪些失败）；已存在的条目只点亮开关不覆盖修改。

**连接测试总是超时？**
npx / uvx 型服务首跑要下载依赖，60 秒内可能跑不完——先用终端手动跑一次让它把依赖装好，再回来重测。

**写入某家 CLI 的配置没生效？**
确认该 CLI 已安装（未安装的会被跳过、不建目录）；重启对应 CLI 让其重读配置。

**HTTP 工具保存被拒？**
请求头与请求体参数同名会冲突；每行参数说明必填（这是智能体理解参数的文档）。

**自签名证书的接口调不通？**
默认校验 TLS。自签名端点可用环境变量 `GROMANG_INSECURE_TLS=1` 放行（自担风险）。

**本机工具为什么不实际执行？**
默认是预览模式（安全默认）。确认没问题后切「真实执行」，写操作仍会走审批。

**市场条目没有一键安装按钮？**
该条目无标准安装方式，点「查找配置」预填表单，自己粘配置入库。
