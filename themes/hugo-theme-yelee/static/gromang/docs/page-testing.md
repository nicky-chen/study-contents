## 一、智能化测试是什么

入口：侧栏「扩展」分组 → **「智能化测试」**。页头标题右侧有**引擎下拉**，三个引擎共用这一个入口（选择会被记住，也支持深链接直达指定引擎）：

| 引擎 | 面向 | 一句话 |
|---|---|---|
| **页面测试**（本篇主角） | 网址 | 黑盒测试：检查登录、表单、页面跳转与可见结果；对着网址干，不需要项目目录；录制流程还能转入项目测试生成脚本 |
| 项目测试 | 项目目录 | 在你的代码仓库里维护自动化用例（依赖 e2e CLI） |
| 接口测试 | 接口与业务链路 | 套件编排 + 确定性断言的接口测试工作台 |

### 项目测试（项目目录里的用例）

- 在你的代码仓库目录里维护自动化用例，跑在项目专属的 e2e 运行时上；
- 一次性会话模型：不支持续聊 / 分叉——发起新任务即开新会话；
- 页面测试录制的流程可以转入项目测试生成脚本；
- 前置：e2e CLI 与 Node.js（设置 → 插件 → 办公插件安装）；项目目录无效或引擎未就绪时，按项目行提示处理后重试。

### 接口测试（接口与业务链路）

- **套件编排**：步骤支持 HTTP 内联请求、引用 HTTP 工具与远程 MCP 工具；变量按 环境 → 套件 → 步骤 → 提取池 四层作用域取值；
- **确定性断言**：判定权不落 LLM（AI 只做降噪建议与归因），结果可复现、可回归；
- **资产两类**：接口集合（承接新建与 HAR / Postman / YApi / Apipost 导入）与自动化场景（从集合选取接口的快照副本，独立保存编排、变量与报告；集合更新不自动覆盖场景）；
- 运行前必过**预检**；「停止」是步骤边界取消——未执行步骤标 skipped，不中断已发出的请求。

页面测试的核心理念（也是智能体被强制遵守的纪律）：**快照为据**——每次动作前先观察页面，以页面快照为事实依据构建定位再操作，不靠盲猜选择器；动作前后都有观察，点错率低、错了能自己纠正。所以它遇慢站、遇改版，都比传统「写死选择器」的脚本稳。

## 二、界面与第一条链路

页面测试工作区从上到下：**地址栏** → **站点审批条**（有待审批站点时才出现）→ **会话工具条** → **实时画面**（可镜像查看）→ 悬浮的**「页面测试助手」**输入区。

跑通第一条链路只需一步：

1. 在「页面测试助手」输入框用自然语言写目标（placeholder 提示：对话打开目标网页，输入或选任务模板），比如「打开 example.com，截图并提取页面里的表格」。
2. 按 `⌘/Ctrl + Enter` 或点「**开始测试**」。
3. 智能体接管：导航 → 观察 → 操作 → 检查点核验 → 出报告，全程实时画面可见。

不知道写什么就输入 `/` 唤出**任务模板**：打开页面并截图、提取页面表格、翻页采集列表、填表并提交、采集并生成报告、导出 Playwright 脚本——六类现成起点。

测试中你可以随时用工具条**接管操作**（自己上手点，登录、验证码、2FA 都适合这时候处理），完了再**继续测试**；也可以**取消测试**。

## 三、前置依赖

| 依赖 | 用在哪 | 哪里装 |
|---|---|---|
| Google Chrome | 标准模式的浏览器 | 自行安装 |
| uv | 首次运行自动搭建 Python 运行时（固定版本依赖，无需你管） | 设置 → 插件 → 必装插件 |
| Node.js / npx | 智能化测试的操作与观测引擎按锁定版本经 npx 启动 | 设置 → 插件 → 必装插件 |
| Playwright | 流程导出为测试脚本；项目测试也依赖 | 设置 → 插件 |
| e2e CLI | 仅项目测试引擎需要（Node ≥22 或 ≥24） | 设置 → 插件 → 办公插件 |

**兼容模式**（详见第五节）使用句芒智元内置浏览器，首次启用需下载约 115 MB（带 SHA256 校验），不需要本机 Chrome。

## 四、站点白名单与审批

页面测试不是无界面上网：每个站点按**三种能力**管控——**浏览 / 下载 / 上传**，每种能力三种模式——**需要批准 / 始终允许 / 阻止**。规则形如 `https://example.com`（精确源）或 `*.example.com`（全部子域），最多 100 条，在站点的权限弹层里维护。

**遇到未白名单的站点**（需要批准模式）：

- **你自己操作时**：请求挂起，工作区顶部出现**站点审批条**——「此网站请求 XX 权限」+ 站点地址，按钮三选一：**拒绝 / 本次会话允许 / 始终允许**。默认 180 秒无人应答按超时处理。
- **智能体委派执行时**：审批等待窗口收短到 20 秒（避免整场测试挂死）；超时后该次导航被拦截，智能体会**暂停测试**（状态变为「等待人工处理」），并在暂停原因里说明待批准的站点——你在审批条上放行后点「继续测试」，它会重试导航接着干。

选「**始终允许**」时按注册域记录（一次放行覆盖该域全部子域），下次不再打扰。选「拒绝」则该站点请求直接被阻止。

## 五、执行模式

**浏览器选哪个**（工具条菜单）：

- **标准模式**：用本机 Chrome 起独立测试会话（未装 Chrome 会明确提示）。缺 Chrome 或遇浏览器安全校验、页面显示异常时，切下一档。
- **兼容模式**：用句芒智元内置浏览器（Electron），首次使用需下载。兼容模式下开发者工具不可用。

**有没有窗口**：浏览器设置里「运行模式 → **显示独立 Chrome 窗口**」开关。开启后以真实窗口跑真实浏览器（无无头标记、无 UA 仿真），登录、验证码类站点的通过率明显更好。

**慢站超时**：单个动作的超时可配 10–180 秒（默认 20 秒）。目标站点有 WAF 挑战页、跳转链路长时调大它，给挑战页留 reload 后的二次验证时间。

**交互执行 vs 无人值守**：

- **交互执行**：用当前可见会话，遇到登录、验证码、2FA 暂停等你在 Chrome 里完成，适合第一遍跑通；
- **无人值守**：配套安全设置——域名范围（按任务访问 / 仅指定网站）+ **写操作预审**（click / 填表 / 输入 / 按键等写类工具逐个放行，**默认全部拒绝**），适合挂定时后不再看。会话另有四档权限模式（自动 / 编辑 / 跳过 / 严格）控制智能体自主程度。

## 六、断言与判定

页面测试的「检查点」就是断言，五种类型：

| 类型 | 判什么 |
|---|---|
| text | 页面文本包含指定内容 |
| url | 当前 URL 包含指定内容 |
| visible | 元素可见 |
| enabled | 元素可用 |
| count | 元素数量 |

**判定规则**（严格执行，不掺水分）：

- 任一检查点未通过 → **失败**；
- 执行完成、有检查点、无安全问题 → **检查通过**；
- 没有检查点 → **待确认**（会提示「没有可核验的检查点，结果待确认」）。

记住一句产品哲学：**智能体顺利跑完 ≠ 测试通过**。想让结果可判，就给任务加上检查点（「提交后应看到“成功”字样」）。

执行状态枚举：运行中 / 等待人工处理 / 执行完成 / 失败 / 已取消 / 已中断。

## 七、录制与零 token 回放

回放体系的核心是**可回放流程**——两种方式产出：

- **自动录制**：智能体执行任务时，每个动作（导航 / 点击 / 输入…）与检查点、提取动作都会落成流程步骤。执行记录里点「**保存回放流程**」即存为回放任务。
- **手动录制**：自己操作浏览器，用拾取模式点选页面元素、插入断言，录成 E2E 流程——完全不消耗 token。

流程的关键设计：

- 步骤使用**语义定位**（拒绝纯坐标点击等不可回放标识），页面小改版不至于脆断；
- 你的输入值被参数化为 `INPUT_1`、`INPUT_2`……**不存原文**（隐私），回放时再提供；
- 断言可后期编辑期望值与定位；
- 一条流程配**数据集**可跑数据驱动：最多 100 行参数，逐行串行回放。

**回放是确定性执行**：不派智能体、不耗 token，页面不变结果恒定。录一遍 → 之后天天零成本回归，这是「零 token 回放」的含义。

## 八、登录态与凭据

- **登录态快照**：cookies 与 localStorage 按站点存快照（最小权限），回放任务可绑定登录态注入——免得每次回归都重新登录（叠加注入，不清你已有会话）。
- **凭据代填**：保存的站点账号可在匹配站点表单里一键代填。密码只存本机（加密文件或 macOS 钥匙串），**永远不会回显给模型**；没配凭据的任务里，代填工具压根不会出现。
- 交互执行时也可以直接人工登录后保存快照，两条路都通。

## 九、定时回归

回放任务可以挂到调度上做**定时回归**：

- 任务状态机：已保存 → 正在启动（重启后不会重复执行）→ 已启动 / 等待浏览器空闲 / 执行失败 / 已完成 / 已中断 / 已取消；卡片显示最近通过率。
- **到点时浏览器被占用**（比如你正开着交互会话）：任务自动顺延 15 秒重试，不会硬抢。
- **瞬时失败退避**：15 分钟退避重试；**连续 5 次基础设施级失败自动停用**任务（防止坏任务每天空转）；单纯断言失败只标红不停用——测试红灯是发现，不是故障。

## 十、报告、失败留证与导出

侧栏**执行记录**列出历史运行，点开**测试报告**弹窗：检查结果列表（通过 / 未通过徽标）、执行状态与判定。

**判定未通过时自动落盘「失败留证四件套」**：

1. 整页截图（目标元素红框高亮）；
2. DOM 快照；
3. console 日志（最近 500 条）；
4. 失败请求清单。

报告里一键**复制 Bug 单**（标题、步骤、留证齐备，直接贴进工单系统）。

**导出三件套**：报告 JSON、可回放流程 JSON、**Playwright 测试脚本**（`.spec.js`）。「Playwright 与 CI」弹窗还给出参数环境变量示例与原生回放命令，退出码约定：`0` 通过、`1` 断言失败、`2` 不确定/中断、`3` 基础设施错误——CI 按码定论。

执行历史支持清理：保留最近 20 / 50 条、1 / 3 个月或全清。

## 十一、安全模型

页面测试的安全设计值得单独一读：

- **网页内容视为不可信数据**：页面上的文字不会被当作指令执行（防提示注入）；
- **三层门禁**：站点白名单（浏览/下载/上传分权）+ 任务包域名范围 + 写操作预审，任务包侧还有 schema 裁剪与执行前拦截双保险；
- **凭据隔离**：密码不出本机、不进模型上下文；
- **第三方任务包**（zip 导入别人的流程）必须先**预览并批准**才会执行；
- **隐私**：录屏与留证只存本机；人工接管期间不录制；输入值不写入流程文件。

## 十二、常见问题 FAQ

**提示「已有任务在运行，请先停止当前任务」？**
同一时刻只能跑一个页面测试任务，先取消或等当前跑完。

**智能体一直不动 / 卡在导航？**
按超时预算排查：读类操作 3 秒、单动作默认 20 秒（慢站调大）、整场测试上限 30 分钟。导航被拦且提示含「未在网页白名单中」→ 去站点审批条放行（第四节）。

**「未检测到 Chrome」？**
装 Chrome，或切兼容模式（内置浏览器，首次下载约 115 MB）。

**结果一直是「待确认」？**
任务里没加检查点。补上断言（文本包含 / URL / 可见 / 可用 / 数量五类）才有通过/失败判定。

**页面弹出 JS 对话框后卡死？**
弹窗不处理会阻塞页面。观察结果里会提示先处理对话框；60 秒无应答自动取消，也可接管后手动点掉。

**定时任务到点没跑？**
先看状态：`等待浏览器空闲` = 浏览器被人工会话占用，会自动顺延；连续 5 次基础设施失败的任务会被自动停用，去任务卡重新启用。

**项目测试/接口测试报「未检测到 e2e CLI 或 Node」？**
到 设置 → 插件 → 办公插件 安装/升级 e2e CLI 与 Node.js 后重试。

**导出的 Playwright 脚本怎么进 CI？**
报告弹窗 → 「Playwright 与 CI」：按 `INPUT_n` 环境变量传参，原生回放命令退出码 0/1/2/3，CI 按退出码判定。
